Privacy

Nectar has no account, no server and no analytics. What you type into it stays in one folder on your own PC — this page lists exactly what that folder holds, and what leaves the machine when you link a calendar.

The short version

There is no Nectar account and no Nectar backend. The app does not send usage data, crash reports or diagnostics anywhere, because there is nowhere for them to go: the only network requests it makes are the calendar calls you set up yourself.

No data is sold, shared or mined. There is no server holding your tasks, and no third-party analytics library in the app.

What is stored, and where

Everything lives in %LOCALAPPDATA%\Nectar. The folder is yours: copy it, back it up, or delete it.

FileContents
nectar.db An SQLite database: your tasks and their completion dates, the scratchpad note, and one row per focus session.
settings.json Plain text preferences — the shortcut, the hover band and pill switches, card order and visibility, focus length, sound settings, and the calendar client ID and tenant you entered.
Token file The calendar access and refresh tokens, encrypted with DPAPI for your Windows user. Another account on the same machine cannot read them.
nectar.log A diagnostic log the app appends to while it runs. It can include the title of a reminder that fired, so treat it as personal if your event names are.

There is no cloud sync and no hidden copy elsewhere. Pinning Nectar to another machine means copying the folder yourself.

Calendar connections

Linking a calendar is optional and uses OAuth with PKCE against your own client ID: you create the app registration with Google or Microsoft, and paste its ID into Nectar. There is no shared Nectar client credential, and no intermediary server sitting between the app and the provider.

The scopes requested are the narrowest that still show a day:

  • Google — calendar.readonly, read access only.
  • Microsoft — offline_access and Calendars.Read, so the app can refresh a token and read events.

Tokens are sealed with DPAPI (user scope) and never leave the machine. Nectar cannot write to, move or delete anything in your calendar. Google or Microsoft still see the requests the app makes to them, under their own privacy policies — that part is between you and whichever provider you link.

What actually goes online

The app talks to these hosts and no others:

  • accounts.google.com, oauth2.googleapis.com and www.googleapis.com for Google sign-in and events.
  • login.microsoftonline.com and graph.microsoft.com for Microsoft sign-in and events.

There is no update check, no licence check, no heartbeat and no telemetry endpoint. Unlink the calendar and Nectar makes no network requests at all.

This website

The landing page sets no cookies, runs no analytics and loads no third-party scripts. There is no consent banner because there is nothing to consent to.

Two things are outside the page's control:

  • Fonts are served by Google Fonts, which receives the request — your IP address, browser and the page you came from — under Google's privacy policy.
  • Hosting is Vercel, which keeps standard server logs (IP address, user agent, requested path) as any web host does.

No form on this site collects anything, and the site has no database of its own.

Your control

  • Unlink a calendar in Customize → General; the stored tokens are discarded.
  • Revoke access at Google or Microsoft, which cuts Nectar off even if a token were left behind.
  • Delete everything by removing %LOCALAPPDATA%\Nectar while the app is closed. There is no remote copy to clean up.

Questions

Open an issue in the project repository, or read the source: the calendar client and the token store are small enough to check the claims on this page yourself. Licence terms are on the licence page.
